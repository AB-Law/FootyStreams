## Design in one paragraph

Nothing is simulated on the live path. A **buffer** task runs the league's daily tick (in a separate worker
process, so a match being simulated never holds the lock the event loop needs) until a matchday is waiting,
verifies each new log with `verify_match` (a failing match is quarantined and aired as filler) and then waits
for the broadcast to consume one. A **broadcast** task asks the **programme** (rebuilt from the database, so a
restart rebuilds the same list) for the blocks after the **cursor** and hands each to the **player**, which
replays stored events at their playing second on the **clock** and gives them to the **bus**. The bus fans out
to sinks without letting any sink slow the channel. If the buffer is behind, the broadcast airs filler. The
**supervisor** restarts crashing tasks; repeated failure opens a circuit and the channel stays up, `degraded`,
on what exists. The process may be killed at any instant: on restart the cursor says where to resume, a
`resume` marker precedes the replay, and consumers drop the few repeated `(match_id, seq)` ids.

## Deviations from the design

1. **`schemas/broadcast.schema.json` is not exported yet.** A new schema file is a schema change, which bumps
   `SCHEMA_VERSION`; the kickoff event records that version, so every golden digest would change, and the open
   calibration PR already owns that bump. The models exist (`events/broadcast.py`, round-trip tested); the
   export lands with the next milestone that bumps the schema.
2. **The composition root is `cli/engine*.py`, not `runtime/main.py`.** The architecture rules let `runtime/`
   import the league but not the CLI wiring or the seed layer, and the engine needs both to build a world.
3. **No process pool of simulators.** One worker process plays the days; matches inside a matchday are still
   simulated one after another (the design's 4-way matchday parallelism is a performance item, with M8's
   profile: a 56-match season is about 3 s on four workers against a 12 s budget).
4. **`uv run league` is not re-expressed as the engine in instant mode**; it still uses the season runner
   directly (the engine's world step is the same code, so the two agree).
5. **The cursor is saved every `cursor_every` events (default 25), not on every one**, so replay after a crash
   is at-least-once inside that window (the e2e test bounds it); `--cursor-every 1` makes it exactly-once at a
   cost of a database write per event.
6. **Filler is a placeholder segment**, not a replay of archived highlights; the selection by `significance`
   needs the archive and the studio layers.
7. **Programme durations are placeholders** (`Programme` in `runtime/config.py`) the commentary and studio
   layers will replace; the in-world to channel time scale is `day_s` (one week per day by default) but is not
   yet used to space matchdays: matchdays air back to back and the idle days between them run on the buffer.
8. **Quarantine stops at the filler.** The fallback-profile retry and the result-only fallback of 10 section 7
   are M14's; here a failed log simply never airs. (A useful consequence found on the way: the result-only
   simulator's thin logs do not pass `verify_match`, so using it as the production fallback needs its own work.)

## Bugs found by building it

- **Tests could write into the repository that runs them** (fixed, own commit). Git exports `GIT_DIR` and friends
  to hooks, and in a linked worktree always does; the tests that make a throwaway repository then committed an
  "initial" commit onto my branch, switched the worktree, set `core.bare = true` and put a test identity into the
  shared config. An autouse fixture now removes the variables, with a regression test and a decoy-repository run.
- **A save in flight when playback was cancelled collided with the save made on cancel** (`ConflictError` on the
  cursor row; the broadcast task crashed on a graceful stop). Saves are serialised and the cursor only moves
  forward.
- **The broadcast could miss the last matchday**: it read the programme, the buffer then played the final day and
  set `finished`, and the loop exited. The flag is read first.
- **A season was thought finished on day one**: the rollover stage appears in every day's report. A rollover is
  now a new season row.
- `asyncio.sleep` can end a timer tick early on Windows: the real and scaled clocks look again after each sleep.
- The OS frees a killed process's file lock a moment after it exits: `acquire` takes an optional grace period.

## Verification

- Unit: clocks (jump, scale, never backwards), pace parsing; broadcast events round-trip; the bus (order, slow and
  failing sinks isolated, drop-oldest, bounded backpressure, retries, timeouts, flush); sinks and rotation; the lock
  (second engine refused with the holder's pid, **killed holder leaves no stale lock**, grace); cursor and health;
  the programme (ids sorted, durations, quarantine, incomplete matchday, resume rule); the player (every event
  unchanged and in order, **match length within 50 ms of the block on the virtual clock**, half-time segment, resume
  pays no catch-up, cursor saves, cancellation saves, **a one-hour clock jump does not burst**); the supervisor
  (backoff, cap, circuit, healthy reset, cancellation); the buffer; the engine (finite run, stored logs equal aired
  logs, cursor and health, resume mid-match with and without a replay window, graceful stop frees the lock, second
  engine refused, starvation covered by filler, sink isolation inside the engine, quarantine, safe mode, circuit
  open keeps the channel up, a whole season with rollover in seconds on the virtual clock).
- **E12** (`tests/e2e`): the real process, stopped gracefully (Ctrl-Break) or killed, restarted on the same
  database: delivered ids, repeats dropped, equal an uninterrupted run; repeats within the cursor interval.
- `uv run check` green after every commit; `uv run check --tier pr` green at the tip.
