## Verification (final state of the stack)
- `uv run check`: PASS in about 9 s (budget 60 s). Steps: ruff lint, ruff format, mypy --strict, changelog
  fragments, changelog up to date, pytest.
- `uv run check --tier pr`: PASS; **152 tests**, **98.6% branch coverage** (floor 90%).
- Hooks verified locally: a malformed commit message is rejected by `commit-msg`; the pre-commit gate runs.
- Gate canaries: each architecture rule has a test that feeds a deliberately bad module.
- Slice sizes (added + deleted lines versus the previous slice, excluding the lockfile and CHANGELOG.md):
  4: 197, 5: 497, 6: 104, 7: 542, 8: 509, 9: 317, 10: 220, 11: 413, 12: 138, 13: documentation only.

## Deviations from the design
- The Cursor rules generator (`rules sync`) was dropped in favour of hand-maintained paired files.
- Four slices exceeded the 400-line target (5, 7, 8, 11) because tests are included; none passed the 800 cap.
  Slices 5, 7 and 8 could each have been split in two (skeletons / checker, parser / command, rules / commands).
- `changelog check` compares against `origin/main` (else `main`) and includes uncommitted and untracked files, so
  the gate fails on a branch with code changes but no fragment, even before committing.
- The `check` tiers implemented are `fast` and `pr`; `nightly` and `release` arrive with the tests that need them.

## Not verified / owner actions
- CI workflow (Windows, Ubuntu; Python 3.12 and 3.13) has not run; action versions were chosen from memory.
- Branch protection for `main` (needs admin): require a pull request and the `quality` checks, require linear
  history or rebase-merge, block force pushes, require review from CODEOWNERS.
- Cursor's handling of `.cursor/hooks.json` was not exercised inside Cursor.
